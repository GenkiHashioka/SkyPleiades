# 引き継ぎを書く

次のセッションの Claude が、この会話を読まずに作業を再開できるようにする。書いたファイルは、次のセッションの始めに SessionStart フック（`.claude/hooks/session-start.sh`）が読み込む。

## 手順

1. `git branch --show-current` で、作業中のブランチを確かめる。`main` なら、フックは引き継ぎを読み込まない。本人に、どのブランチの引き継ぎかを聞く
2. ファイル名は、ブランチ名の `/` を `-` に置き換えたものにする。保存先は `.claude/handoff/<ファイル名>.md`。例：`chore/3-session-tooling` なら `.claude/handoff/chore-3-session-tooling.md`
3. 同じファイルがすでにあれば読み、今も正しい内容は引き継いだうえで、全体を書き直す。追記はしない
4. 下の形式で書く。会話にないことは書かない。推測は「要確認」と明記する
5. 書いた内容を本人に見せ、次に `/clear` を実行してよいことを伝える

## 形式

```markdown
# <Issue 番号とタイトル>

更新: <YYYY-MM-DD>
ブランチ: <ブランチ名>

## 目的
<この Issue で達成すること。1〜2 行>

## 決めたこと
- <決定>：<理由>。却下した案：<案と理由>

## 状態
- 実装済み / 動作確認済み / 本人が説明済み / 要確認 を区別して書く

## 未解決
- <まだ決めていないこと、詰まっている点>

## 次の一手
- <次のセッションで最初にやること。本人と Claude のどちらがやるか>

## 関連ファイル
- <設計書、journal、ADR、触ったコードのパス>
```

## 書かないこと

- 会話の経緯そのもの。結論と理由だけを残す
- 設計書、journal、ADR にすでに書いた内容。リンクで示す
