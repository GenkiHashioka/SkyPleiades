# Issue に着手する

AGENTS.md 4 章の手順 1〜3（Issue を起票する、ブランチを切る、要件・設計・関連する ADR を読んで設計を相談する）を支える。Claude は読み取りと提案だけを行い、ブランチを切るのは本人とする。

対象の Issue：$ARGUMENTS

## 手順

1. Issue 番号がなければ、本人に聞く
2. `gh issue view <番号> --comments` で、Issue の本文とコメントを読む。閉じた Issue なら、本人にそれでよいかを確かめる
3. `git status` と `git branch --show-current` で、今の状態を確かめる。`main` でない、または未コミットの変更があれば、ブランチを切る前に本人に伝える
4. `docs/decisions/README.md` の一覧から、この Issue に関係する ADR を選んで読む。要件の文書があれば、関係する節も読む
5. ブランチ名を 1 つ推す。形は AGENTS.md 9 章の `<種類>/<Issue 番号>-<トピック>` とし、種類をそれにした理由を添える。トピックは英小文字とハイフンで短く書く
6. ブランチを切るコマンドを示し、各行・各オプションの意味を説明する。Claude は実行しない

   ```bash
   git switch main
   git pull
   git switch -c <ブランチ名>
   ```

7. 下の形式でまとめ、最初に相談する論点を 1 つだけ示す

## まとめの形式

```markdown
## #<番号> <タイトル>

- 目的：<1〜2 行>
- 完了条件：<Issue に書かれたもの>
- 関連する ADR：<番号とタイトル。なければ「なし」>

## ブランチ
<推すブランチ名と理由、コマンドとその説明>

## 最初の論点
<設計や範囲で、最初に決めること。推す案と、比べた案>
```

## しないこと

- 実装を始めない。AGENTS.md 2 章のとおり、まず教える
- Issue の起票、コメント、ブランチの作成などの書き込みの操作をしない
