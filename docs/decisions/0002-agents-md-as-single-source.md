# 0002 - 共通のルールは日本語の AGENTS.md に一本化し、CLAUDE.md から取り込む

**ステータス**: 採用
**日付**: 2026-11-25

## 背景

2 つの AI は、それぞれ別のファイルを自動で読む。

| AI | 自動で読むファイル |
|---|---|
| Claude Code | `CLAUDE.md` |
| Codex | `AGENTS.md` |

KotlinTodo では、役割分担、Git / PR の運用、技術ブログの題材などのルールを、`CLAUDE.md`（日本語）と `AGENTS.md`（英語）の両方に書いていた。同じルールが 2 か所にあると、片方だけを直したときに食い違う。KotlinTodo でも、途中から `CLAUDE.md` の文書の更新手順を `AGENTS.md` へのリンクに置き換えるなど、重複への手当てが必要になっていた。

また、KotlinTodo の `AGENTS.md` は英語で書かれていたが、ルールを読み、直し、レビューするのは本人である。英語のルールは、日本語のものより読み落としや直し漏れが起きやすい。

Claude Code には、`CLAUDE.md` に `@ファイルのパス` と書くと、そのファイルの中身を取り込む仕組み（import）がある。Codex には同じ仕組みがない。

## 決定

### 1. 共通のルールは `AGENTS.md` にだけ書く

両方の AI に当てはまるルール（役割、責任の範囲、開発の進め方、文書の更新手順、Git / PR の運用、説明の仕方など）は、`AGENTS.md` にだけ書く。

### 2. `CLAUDE.md` は `@AGENTS.md` で取り込み、Claude Code に固有のことだけを書く

`CLAUDE.md` の先頭に `@AGENTS.md` を書く。そのほかには、Claude Code にだけ関係すること（Codex プラグインのコマンド、`/handoff` と `/clear` の運用、開始時フック）だけを書く。

### 3. リポジトリの文書とやりとりは日本語にそろえる

`AGENTS.md` と `CLAUDE.md` を含むリポジトリの文書、コミットメッセージ、Issue、PR は日本語で書く。コード、識別子、ファイル名、日本語にすると分かりにくくなる技術用語は英語のままでよい。

### 4. 全体用の `CLAUDE.md` と重なるルールも `AGENTS.md` に書く

ユーザー全体の設定（`~/.claude/CLAUDE.md`）にある個人開発の方針は、Claude Code しか読まない。そのため、Codex にも守ってほしいもの（本人を主役に書く、コマンドの中身を説明する、論理名（物理名）の書き方など）は、`AGENTS.md` にも書く。

## 得られるもの

- **ルールを変えるときに直すのが 1 か所で済む**：2 つの AI が、同じ文を読む
- **本人がルールを読み、直しやすい**：すべて日本語なので、レビューの負担が減る
- **`CLAUDE.md` が短くなる**：Claude Code に固有のことだけが残る

## 犠牲にするもの

- **Claude Code がルールを知るかどうかが、取り込みの仕組みに依存する**：`@AGENTS.md` が効かなければ、Claude Code は共通のルールを読まない。Issue #2 の完了条件で、新しいセッションに読み込まれていることを確かめる
- **全体用の `CLAUDE.md` との重複は残る**：重なるルールを変えるときは、両方を確認する必要がある

## 検討した代替案

- **KotlinTodo と同じく、両方のファイルに書く**：今のやり方をそのまま使えるが、食い違いが起きる問題が残る。KotlinTodo でもすでに手当てが必要になっていた。却下
- **`CLAUDE.md` を正本にして、`AGENTS.md` から参照させる**：Codex には取り込みの仕組みがない。「`CLAUDE.md` を読むこと」と書いても読むかどうかは Codex 次第で、確実ではない。却下
- **`CLAUDE.md` を `AGENTS.md` へのシンボリックリンク（別のファイルを指す特殊なファイル）にする**：Windows ではシンボリックリンクを作るのに追加の設定が要り、Git での扱いも環境によって変わる。また、Claude Code に固有のことを書く場所がなくなる。却下
- **`AGENTS.md` を英語で一本化する**：本人がふだん読み、直す文書が英語になり、レビューの負担が増える。却下
