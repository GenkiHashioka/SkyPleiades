# #3 セッションの引継ぎと Issue 着手の道具を用意する

作成：2026-11-28

## 目的

セッションをまたいでも作業を再開しやすくする。あわせて、Issue から始める運用を道具で支える。KotlinTodo の `/handoff` と開始時フックを、クローンが 1 つの Windows の環境に移す。

## やったこと

- 開始時フック（`.claude/hooks/session-start.sh`）を、KotlinTodo 版から移して書いた
  - 2 つのクローンを見るループと配列をなくし、今のブランチを 1 回調べて、1 つの `if` で引き継ぎを読むか決める形にした
  - JSON を作る部分を、`python3` から `node -e` の `JSON.stringify` に替えた
- フックを `.claude/settings.json` に登録した。`matcher` は `startup|clear|compact` で、`resume` は外した。再開した会話には前の内容が残っているので、引き継ぎを渡すと二重になるため
- `.gitignore` を作った。`.claude/*` で中身をすべて外し、`settings.json`、`skills/`、`hooks/` だけを `!` で戻す。引き継ぎや `settings.local.json` がコミットされないようにするため
- `/handoff`（`.claude/skills/handoff/SKILL.md`）を KotlinTodo から移し、`/start-issue`（`.claude/skills/start-issue/SKILL.md`）を新しく作った（Claude が下書き、本人がレビュー）
- `CLAUDE.md` の「セッションの区切り」を実際の動きに合わせ、「`.claude/` のコミット」の節を足した（Claude が下書き、本人がレビュー）

## 決めたこと

- **`/start-issue` の範囲**：#3 では、Issue と関連する ADR を読み、ブランチ名とコマンドを示すところまでにした。設計書のひな形を作る手順は、設計書の種類を決める #4 で足す。却下した案は、#4 のあとに一度に作る案（#3 を開き直すことになる）と、作らずに Backlog に送る案（ADR を読むことやブランチ名の規則を守れるかが、その場の Claude しだいになる）
- **JSON の作り方**：Node.js にした。Windows の `python3` は、Microsoft Store へ案内する仮のコマンドで動かない。Python を入れる案は、この数行のためだけに管理するものが増えるので採らなかった。今は Python を使う予定もない。ただの文字列を出す案は、画面に 1 行出す `systemMessage` が使えなくなるので採らなかった
- **書く人の分担**：スクリプトと設定は本人、スキルと `CLAUDE.md` は Claude が下書きした。スクリプトは移植が中心で量が少なく、完了条件の「説明できる」に直接つながるため
- **`/start-issue` には `disable-model-invocation` を付けない**：「#<番号> をはじめましょう」と言うだけで使えるようにするため。読んで提案するだけで、ファイルも Git も書き換えないので、Claude が自分の判断で使ってもリスクが小さい。`/handoff` は引き継ぎを上書きするので、本人が打ったときだけ動かす
- **Issue を起票するタイミング**：要件から MVP の範囲を粗く Issue に切り出すのを基本にし、作業中に見つけた範囲外のことは、すぐ別の Issue にする。文書にするのは、要件の文書を作る #4 で行う

## 途中で変えたこと

- **`.git` があるかを調べる行を消した**：KotlinTodo 版は `[ -d ... ] || continue` でクローンを飛ばしていた。ループがなくなって `continue` が使えなくなった。`exit 0` に替えると、失敗しても何も出ずに気づけない。`CLAUDE_PROJECT_DIR` はいつもリポジトリを指し、`.git` がない状況はほぼ起きないので、行ごと消した
- **`/handoff` の手順に「前の引き継ぎを読み、今も正しい内容は残して書き直す」を足した**：KotlinTodo 版の「上書きする」だけだと、そのセッションで話題にしなかった決定が消えるおそれがあるため

## 学び

- SessionStart フックは、標準出力に JSON を書くと、`additionalContext` が Claude のコンテキストに入り、`systemMessage` が画面に 1 行出る。フックが失敗してもセッションは始まるので、失敗に気づける手がかりを残しておく
- bash の文法の多くは、Kotlin に置き換えて読める。`${変数:-代わりの値}` はエルビス演算子（`?:`）、`"$変数"` は文字列テンプレート、配列の `${#配列[@]}` は `size` にあたる
- `node -e` のうしろを `'...'` で囲むのは、bash に中身を展開させないため。`"..."` で囲むと、`$` が展開されるうえ、JavaScript の中の `"` で bash の文字列が終わってしまう
- `.gitignore` で `.claude/` と書くとフォルダごと外れ、git がその中を見なくなるので、`!` で一部を戻せない。`.claude/*` と書く
- VS Code は、拡張機能なしでは `.editorconfig` を読まない。新しく作ったファイルが CRLF で保存されていた。シェルのスクリプトが CRLF になると、bash は `\r` をコマンドの一部と読んで壊れる。拡張機能「EditorConfig for VS Code」を入れて対処した

## ブログ題材候補

- **Windows に python3 がなくても動く Claude Code の SessionStart フック**

  - 新しいファイルが CRLF になる理由と、EditorConfig 拡張での対処
